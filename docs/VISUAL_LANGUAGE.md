# Visual Language

## Purpose

This document defines how Eco-Sense should look and feel at a product level. Detailed numeric implementation values live in [`DESIGN_TOKENS.md`](DESIGN_TOKENS.md). Component-level rules live in [`COMPONENT_SPECIFICATION.md`](COMPONENT_SPECIFICATION.md).

## Direction

Eco-Sense should look like a calm environmental intelligence platform, not a student IoT dashboard. The UI should feel precise enough for researchers and administrators, but simple enough for farmers using Android phones outdoors.

## Visual qualities

Use:

- quiet neutral surfaces,
- environmental accent colors,
- large readable values,
- soft borders,
- restrained elevation,
- generous mobile spacing,
- chart labels that explain meaning,
- subtle state transitions.

Avoid:

- neon palettes,
- decorative gradients everywhere,
- dark cyberpunk dashboards,
- gaming visuals,
- generic admin templates,
- dense technical chrome on public pages,
- floating UI elements without purpose.

## Public visual language

Public pages should feel open, clear, and reassuring.

Rules:

- Use larger type and more whitespace.
- Put environmental status before navigation complexity.
- Use cards as meaning groups, not decoration.
- Use charts sparingly and explain them.
- Keep controls minimal.
- Keep report actions visible and reachable.

## Admin visual language

Admin pages should feel efficient, precise, and stable.

Rules:

- Use denser layouts than public pages.
- Prefer tables for station operations.
- Keep filters and actions visible.
- Use small but readable badges.
- Show audit and event history clearly.
- Avoid marketing-style oversized sections.

## Environmental data language

Environmental data should be visually honest.

Rules:

- Show units beside values.
- Show freshness near status.
- Show thresholds on charts when relevant.
- Avoid false precision.
- Do not show confident healthy state when data is stale or sensor is faulty.

## Imagery

Use imagery only when it supports community, environment, field deployment, or education.

Rules:

- Prefer real field photos if available and consent-safe.
- Avoid generic stock technology photos.
- Avoid decorative sensor illustrations that imply features not built.
- Never let imagery compete with current environmental status.

## Brand restraint

Eco-Sense can look modern, but it should not feel like a SaaS product detached from the community. The strongest brand signal should be trust: clear data, calm status, reliable behavior, and useful public access.
